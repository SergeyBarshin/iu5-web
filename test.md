Чек-лист "Порядка показа"

1. Выполнить метод аутентификации через Swagger в режиме инкогнито.

Статус: ✅ Готово.
Как показать:

1. Открываете http://localhost:8080/swagger/index.html в режиме инкогнито.
2. Находите эндпоинт POST /api/v1/users/login.
3. Нажимаете "Try it out", вводите JSON с логином/паролем существующего пользователя (например, того, которого вы создадите через POST /register).
4. Выполняете запрос. В ответе вы получите JWT-токен.
5. Получить список заявок в Swagger.

Статус: ✅ Готово.
Как показать:

1. В Swagger UI, вверху справа, есть кнопка "Authorize". Нажимаете ее.
2. В появившемся окне вставляете токен, полученный на предыдущем шаге, в формате Bearer <ваш_токен>. Например: Bearer eyJhbGciOiJIUzI1NiIsInR5c....
3. Нажимаете "Authorize", затем "Close". Теперь все запросы в Swagger будут отправляться с этим заголовком.
4. Находите эндпоинт GET /api/v1/dividend-calculations.
5. Нажимаете "Try it out" и "Execute".
6. Результат: Вы увидите список заявок, доступных этому пользователю.
7. Использовать JWT из ответа аутентификации для заголовков authorization в Insomnia/Postman.

Статус: ✅ Готово.
Как показать:

1. Копируете токен, полученный в Swagger или Postman.
2. В Postman, для любого защищенного запроса (например, GET /api/v1/users/me), переходите на вкладку Authorization.
3. Выбираете тип Bearer Token.
4. В поле Token вставляете скопированный JWT.
5. Отправляете запрос. Он должен выполниться успешно.
6. В Insomnia/Postman выполнить GET списка заявок: 401/403 для гостя, для создателя только его заявки.

Статус: ✅ Готово.
Как показать:

- 401 Unauthorized (гость): Отправьте запрос GET /api/v1/dividend-calculations без заголовка Authorization. Вы получите ошибку 401 Unauthorized.
- Для создателя только его заявки:
  Заранее подготовьте данные: создайте двух пользователей (например, user1 и user2).
  Залогиньтесь под user1 и создайте пару заявок.
  Залогиньтесь под user2 и создайте одну свою заявку.
  Теперь залогиньтесь снова под user1 (получите его токен).
  Выполните GET /api/v1/dividend-calculations с токеном user1.
  Результат: В ответе будут только заявки, созданные user1. Заявка от user2 не будет видна. Это доказывает, что фильтрация по creator_id работает.

5. Выполнить PUT завершения заявки: для создателя 403 статус, для модератора успех.

Статус: ✅ Готово.
Как показать:

1. Заранее подготовьте данные:
   user1 (обычный пользователь, is_moderator: false).
   moderator1 (модератор, is_moderator: true). Это можно сделать, вручную изменив флаг в БД через Adminer.
   Заявка, созданная user1 и находящаяся в статусе submitted. Пусть ее id=5.
2. Сценарий создателя (ошибка):
   Получите токен для user1.
   Отправьте запрос PUT /api/v1/dividend-calculations/5/moderate с этим токеном и телом {"status": "completed"}.
   Результат: Вы получите ошибку 403 Forbidden с сообщением "Moderator access required" или "you are not a moderator".
3. Сценарий модератора (успех):
   Получите токен для moderator1.
   Отправьте тот же запрос PUT /api/v1/dividend-calculations/5/moderate с токеном модератора.
   Результат: Запрос выполнится успешно (200 OK), статус заявки изменится, и дивиденды рассчитаются.
4. Выполнить GET списка заявок - для модератора все заявки.

Статус: ✅ Готово.
Как показать:

1. Используя данные из пункта 4 (где есть заявки от user1 и user2).
2. Получите токен для moderator1.
3. Выполните GET /api/v1/dividend-calculations с токеном модератора.
4. Результат: В ответе будут все заявки, и от user1, и от user2. Это доказывает, что проверка if !isModerator в GetCalculationsList работает.
5. Показать содержимое Redis через cmd, для сессий показать пользователя.

Статус: ✅ Готово.
Как показать:

1. Сначала выполните POST /logout для любого пользователя. Это добавит его токен в черный список в Redis.
2. Откройте терминал и подключитесь к CLI Redis внутри контейнера:
